  <action>
Fix the `build_metadata_write_filter` function (lines 362-382) to write metadata at the global/format level using `-metadata:g` instead of `-metadata` (no specifier).

**Root cause:** In FFmpeg, `-metadata key=value` (no stream specifier) writes metadata to the default stream (typically the video stream). The `probe_global_metadata` function reads `format.tags` which contains only global/container-level metadata. These are two different metadata scopes.

**Fix:** Change the metadata argument from `-metadata` to `-metadata:g` for each field. The `:g` specifier tells FFmpeg to write to the global/format metadata scope, which is what `probe_global_metadata` reads via `format.tags`.

Change line 377:
```rust
// Before:
args.push("-metadata".to_string());
// After:
args.push("-metadata:g".to_string());
```

Also, ensure input metadata is carried forward. When processing a source that already has metadata, we want to preserve existing fields and overlay our fake ones. To do this, add `-map_metadata 0` at the start of the args vector. This tells FFmpeg to copy all metadata from input stream 0 first, then our `-metadata:g` fields override/add to it.

```rust
// At the start of the function, before the loop:
let mut args = vec!["-map_metadata".to_string(), "0".to_string()];
```

Without `-map_metadata 0`, FFmpeg may create output with no metadata track at all if the input has none (common for lavfi-generated sources), and our `-metadata:g` fields may be silently dropped.

The complete fix in the function:
1. Add `-map_metadata 0` as first argument (preserve existing metadata, create metadata track if none exists)
2. Change `-metadata` to `-metadata:g` in the field loop (write to global format scope)

The test source is generated from lavfi (which produces no input metadata), so the `-map_metadata 0` won't copy anything but ensures a metadata track exists in the output, allowing `-metadata:g` to write to it.
