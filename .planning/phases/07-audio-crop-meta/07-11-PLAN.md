```rust
/// Run ffprobe to count video frames in a file.
fn count_frames(filepath: &str) -> Result<u32, String> {
    let output = Command::new(ffprobe_bin())
        .args([
            "-v", "quiet",
            "-select_streams", "v:0",
            "-show_entries", "stream=nb_read_frames",  // <-- missing -count_frames
            "-of", "csv=p=0",
            filepath,
        ])
        .output()
        .map_err(|e| format!("ffprobe: {}", e))?;
    let text = String::from_utf8_lossy(&output.stdout).trim().to_string();
    text.parse::<u32>().map_err(|e| format!("parse frame count '{}': {}", text, e))
}
```

The issue: `nb_read_frames` is only populated when ffprobe is told to actually count frames via the `-count_frames` flag. Without it, ffprobe returns `N/A` for containers/codecs that don't store the frame count in the stream header (e.g., variable frame rate content, certain MP4 files produced by lavfi or some encoders).

The fix: Add `-count_frames` before `-show_entries` in the ffprobe arguments. This tells ffprobe to actually decode/count all packets in the stream and populate `nb_read_frames`.

Also add a fallback: If `-count_frames` still returns empty/N/A (extremely rare), fall back to counting via `-show_entries stream=nb_frames` (the header-encoded frame count) and parse that as an alternative.

Fix the `count_frames` helper function (lines 90-104) in two ways:

**Primary fix: Add `-count_frames` flag**

Insert `-count_frames` into the ffprobe argument list before `-show_entries`. This tells ffprobe to actually decode the stream and count all packets, populating `nb_read_frames` with a real integer. Without this flag, `nb_read_frames` returns `N/A` for containers that don't store frame count in the header.

```rust
fn count_frames(filepath: &str) -> Result<u32, String> {
    let output = Command::new(ffprobe_bin())
        .args([
            "-v", "quiet",
            "-count_frames",           // <-- ADD THIS: force frame counting
            "-select_streams", "v:0",
            "-show_entries", "stream=nb_read_frames",
            "-of", "csv=p=0",
            filepath,
        ])
        .output()
        .map_err(|e| format!("ffprobe: {}", e))?;
    let text = String::from_utf8_lossy(&output.stdout).trim().to_string();
    
    // Try to parse the count
    if let Ok(count) = text.parse::<u32>() {
        return Ok(count);
    }
    
    // Fallback: try nb_frames (stream header frame count) if nb_read_frames is N/A
    let output2 = Command::new(ffprobe_bin())
        .args([
            "-v", "quiet",
            "-select_streams", "v:0",
            "-show_entries", "stream=nb_frames",
            "-of", "csv=p=0",
            filepath,
        ])
        .output()
        .map_err(|e| format!("ffprobe fallback: {}", e))?;
    let text2 = String::from_utf8_lossy(&output2.stdout).trim().to_string();
    text2.parse::<u32>().map_err(|e| format!("parse frame count '{}': {}", text2, e))
}
```

The fallback to `nb_frames` handles the edge case where even `-count_frames` doesn't populate `nb_read_frames`. While rare with `-count_frames`, some FFmpeg builds or formats might still return `N/A`. The `nb_frames` field is set by the muxer and is more commonly populated for well-formed files.

Note: `-count_frames` can be slow for large files because it decodes every packet. For integration tests with ~60-frame test videos, this is negligible (~100ms). This helper is only used in tests, not in production code paths.
